# Telegram-бот: сводка чата за 24 часа

Бот собирает сообщения группы и отправляет **одну картинку с короткой подписью** по команде `/dashboard` и ежедневно в настроенное время.

## Обновление 2.1: короткая сводка, темы по структуре

- **Кратко по умолчанию.** Три главные темы, одна строка сути или итога на тему и компактный IQ*. Вся подпись — не более 900 единиц UTF-16, включая эмодзи; длинных текстовых сообщений следом нет. Изображение также показывает только три главные темы.
- **Кнопка «💬 Темы».** Подробности одной темы на странице: заголовок, число сообщений и участников, **суть → вопрос → итог**, ключевые слова. Каждый фрагмент ведёт к исходной реплике. Раздел появляется только при наличии подходящей реплики: бот не придумывает решения.
- **Кнопка «🧠 IQ*».** Пять компонентов оценки, достаточность данных и пояснение — по одному участнику на странице. Доступны все участники с оценкой.
- **Без новых сообщений при просмотре.** «Назад» и «Далее» листают подпись к той же картинке; «Кратко» возвращает исходную сводку. Изменение видно всем в группе.
- **Лучше группировка и приоритет.** Связь ответов помогает соединять части одного обсуждения, если у реплики есть несколько общих значимых слов с другой частью. Повтор одной реплики не увеличивает вес темы в рейтинге. Исходное количество сообщений учитывается полностью.
- **Подробности после перезапуска.** Готовая сводка сохраняется в SQLite на 24 часа с момента создания. Новая переписка не меняет страницы старой сводки. После истечения срока кнопка предлагает создать новый отчёт.

Пример подписи:

> **📊 Сводка · 24 часа**
>
> 96 сообщ. · 8 участн. · 3 фото
>
> **1. Установка драйвера NVIDIA** · 18 сообщ.
>
> Итог: сон монитора заработал после обновления драйвера.
>
> **2. Бронирование кафе** · 12 сообщ.
>
> Суть: выбирали столик на субботний вечер.
>
> **IQ* 103** · Аня 108, Борис 101
>
> *Игровой балл текста, не оценка интеллекта.*

Содержательные слова по-прежнему приводятся к начальной форме; служебные слова, ссылки, команды и упоминания отфильтровываются. Счётчик слов показывает число сообщений с этим словом. Для подробного просмотра доступны девять основных тем и общий блок остальных обсуждений. Отдельные реакции без содержательных слов учитываются в активности, но могут остаться вне тем.

Анализ работает **локально**, без ключей API, платных запросов и загрузки нейросетей. Для русской морфологии используется `pymorphy3` со словарём, устанавливаемым вместе с зависимостями. Русский поддерживается морфологически; английские термины обрабатываются без полноценной английской лемматизации, для казахских служебных слов есть базовый фильтр. Заголовки и содержание извлекаются из переписки: бот не генерирует новые факты и не определяет правдивость сообщений. Синонимы, сарказм и полностью неявный контекст локальный алгоритм может распознать неточно.

## Как считается IQ*

Это **игровой показатель текста за сутки, а не измерение интеллекта человека**. Шкала остаётся 70–130, компоненты показываются от 0 до 100:

| Компонент | Доля | Что учитывается |
| --- | --- | --- |
| Словарь | 18% | Разнообразие значимых слов в скользящих окнах, а не простое отношение уникальных слов ко всей переписке |
| Развёрнутость | 24% | Число разных значимых слов в неповторяющихся сообщениях; длина ограничена сверху |
| Аргументация | 28% | Объяснения причин, примеры, сравнения и условные рассуждения с содержательным продолжением |
| Диалог | 18% | Ответы другим участникам и тематические продолжения недавних реплик; ответы себе не засчитываются |
| Структура текста | 12% | Плотность значимых слов и небольшой вклад структуры предложений; это не проверка грамотности |

Точные и близкие повторы сообщений не улучшают компоненты или достаточность данных и дают штраф. Порядок слов и добавленные числа не делают копию новым содержанием. Повторы одного слова внутри сообщения также снижают результат. Отдельное «потому что» или «например» без содержательного продолжения не считается аргументом. Это признаки формы текста, а не проверка логической правильности аргумента.

Минимум для появления оценки — два сообщения и восемь значимых слов. При малой выборке результат сдвигается ближе к 100 и помечается как предварительный. Достаточность данных зависит от числа неповторяющихся сообщений и объёма их текста; отметки «низкая / средняя / высокая» не являются статистической оценкой достоверности реального IQ. Формула детерминированная, случайных баллов нет.

## Что ещё входит в отчёт

Общее число сообщений и фотографий, активные участники, активность по часам и до шести фотографий с реакциями или ответами. Служебные события Telegram в статистику сообщений не входят.

В публичных группах используются ссылки `t.me/имя_группы/номер`, в закрытых супергруппах — `t.me/c/…`; закрытые ссылки доступны участникам группы. В обычной группе Telegram не поддерживает ссылки на отдельные реплики: после преобразования в супергруппу они появятся в новых отчётах.

Фото ранжируются по сумме реакций и прямых ответов за сутки. При равенстве выше фото с большим числом реакций, затем более новое. Для событий реакций бот должен быть **администратором группы**; иначе доступны только ответы. Старые реакции задним числом не появятся. Фото без реакций и ответов не показываются, пустого блока фотографий нет.

Оформление сохраняет портрет `assets/silver_guardian.jpg`, серебряные акценты и полупрозрачные тёмные карточки. Если изображения нет, используется однотонный фон.

## Запуск

1. Создайте бота через [@BotFather](https://t.me/BotFather) и скопируйте токен. Не публикуйте его и не записывайте в файлы проекта.
2. Назначьте бота **администратором группы**, чтобы он получал обычные сообщения и события о реакциях. Если реакции не нужны, можно вместо этого отключить режим приватности: BotFather → `/setprivacy` → выберите бота → **Disable**, затем добавьте бота в группу **заново**.
3. Установите Python 3.11 или новее. В папке проекта выполните:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:BOT_TOKEN = "токен_от_BotFather"
$env:DASHBOARD_TZ = "Asia/Qyzylorda"
$env:AUTO_REPORT_TIME = "09:00"
.\.venv\Scripts\python.exe bot.py
```

В Linux/macOS используйте `python3 -m venv .venv`, затем `.venv/bin/python` вместо `py` и Windows-пути. Часовой пояс задаётся переменной `DASHBOARD_TZ` в формате IANA; по умолчанию используется UTC.

4. Напишите `/dashboard` в группе. `/help` показывает краткую справку. Ежедневный отчёт отправляется автоматически в `AUTO_REPORT_TIME` по часовому поясу `DASHBOARD_TZ`. Время задаётся в формате `HH:MM`, по умолчанию `09:00`. Бот должен оставаться запущенным постоянно; раздел хостинга **Scheduled commands** для этого не нужен.

Можно задать путь к базе: `DASHBOARD_DB=...`. По умолчанию рядом с ботом создаётся `dashboard.sqlite3`. На хостинге для этой базы нужен постоянный диск: в ней находятся сообщения за 24 часа, готовые сводки для кнопок и отметки об уже отправленных ежедневных отчётах. Если хостинг удаляет файлы при перезапуске, сводка потеряет накопленную историю, а автоматическая отправка может повториться.

## Обновление установленного бота

В каталоге проекта получите изменения и обновите зависимости в том же окружении, где запускается бот:

```bash
git pull
.venv/bin/python -m pip install -r requirements.txt
```

В Windows вместо `.venv/bin/python` используйте `.\venv\Scripts\python.exe`. Затем перезапустите процесс бота привычным способом. Дополнительные зависимости для версии 2.1 не нужны. Настройки запуска, токен и существующая SQLite-база подходят; таблица готовых сводок создаётся автоматически, удалять базу не требуется. Новый анализ применяется к уже накопленным сообщениям за последние сутки.

## Важное ограничение Telegram

Бот **не может прочитать старую историю** до своего добавления. Первые 24 часа отчёт будет постепенно заполняться. Если режим приватности включён, отчёт будет неполным. Telegram хранит неполученные обновления не более 24 часов, поэтому процесс лучше держать постоянно запущенным.

Бот хранит текст, имена отправителей и Telegram ID фотографий в локальной SQLite-базе. Исходные сообщения старше 24 часов удаляются при обработке сообщений и во время ожидания новых. Готовые сводки с извлечёнными фрагментами хранятся отдельно 24 часа после создания, затем тоже удаляются. Сами фотографии загружаются только для построения отчёта и в базе не хранятся. Изображение отчёта отправляется обратно в тот же групповой чат. Команда `/dashboard` в личном чате не раскрывает данные группы.

## Проверка без Telegram

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe demo.py
```

`demo.py` создаёт `demo_dashboard.png` с вымышленными данными и `demo_compact.png` без фотографий.
